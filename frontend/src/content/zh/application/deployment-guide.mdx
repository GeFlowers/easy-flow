# 部署指南

当前只维护 Windows 本机应用部署。前端监听 `127.0.0.1:3001`，后端监听 `127.0.0.1:8001`，Nginx 提供 `http://localhost:2026` 统一入口。

## 配置

根目录 `.env` 保存真实凭据，不要提交。数据库连接指向 `127.0.0.1:5432`，Redis 指向本机的服务地址。配置中的 `database.postgres_url: $DATABASE_URL` 引用环境文件。

`NGINX_HOME` 指向包含 `nginx.exe` 的安装目录。先备份原配置，再复制仓库 `deploy/nginx/nginx.conf` 到其 `conf/nginx.conf`。代理会把 `/api/langgraph/*` 改写为后端的 `/api/*`，其余接口与页面保持同源访问。

## 启动和停止

按[快速上手](/docs/application/quick-start)准备依赖后执行：

```bash
bash scripts/start.sh
bash scripts/stop.sh
```

关闭脚本会停止前后端和数据库容器，但不会删除数据库卷。

## 代理开机自启

代理可以通过系统任务配置为开机启动。无需登录 Windows，也不保存个人密码。前后端仍需手动启动；只有代理运行时，访问应用会得到上游不可用响应。

代理由其安装目录中的程序单独管理。操作系统账户运行的代理可能需要管理员权限。后端日常运行不要使用管理员账户。

## 数据与安全

- 数据库卷固定为 `deer-flow-dev_postgres-data`，已有卷缺失时启动明确失败，不会自动创建空库。
- 附件、产物、长期记忆和自动生成的登录签名密钥位于 `backend/.deer-flow`，需要单独备份。
- 认证由后端处理，不依赖旧版教程中的 Better Auth 配置。
- 本机沙箱中的命令以运行后端的账户权限执行，不是容器隔离。
- 默认只允许本机访问。公开部署前需要另行设计传输加密、网络边界、凭据管理和备份，不能直接视为生产安全配置。
