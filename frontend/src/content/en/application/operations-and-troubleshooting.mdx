# Operations and Troubleshooting

## Logs and status

Application logs are in the project `logs` directory. Inspect database logs with your container manager; Nginx logs are in its installation directory.

```bash
Get-Content logs/gateway.err.log -Tail 50
Get-Content logs/frontend.err.log -Tail 50
```

Check for credentials before sharing logs. Do not print the entire environment file.

## Common problems

- Unavailable upstream: start the application with `bash scripts/start.sh` and inspect its logs. Nginx boot startup does not start the frontend or backend.
- Database connection failure: verify the container, original volume, local address and credentials. Do not replace a missing migration source with an empty volume.
- Redis connection failure: check the local service, connection address and authentication settings.
- Port conflict: the launcher refuses to start; identify the owner instead of terminating all processes with the same name.
- Model request failure: check model configuration, credential availability and connectivity without exposing credentials.
- Build failure: run `corepack pnpm build` in the frontend directory; see the quick start for dependency installation.
- Tool or file failure: check host paths and account permissions. The sandbox no longer resolves paths inside an application container.

## Updating and restarting

```bash
bash scripts/stop.sh
cd frontend && corepack pnpm build && cd ..
bash scripts/start.sh
```

Reinstall dependencies after they change. Restart the frontend and backend after environment changes; reloading Nginx alone does not reload their environment.

## Backups

Back up PostgreSQL, the complete `backend/.deer-flow` directory and private configuration separately. Normal backend shutdown flushes queued memory updates; do not replace it with forcibly terminating the process.
