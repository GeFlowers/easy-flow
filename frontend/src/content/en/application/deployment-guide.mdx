# Deployment Guide

This learning edition supports a Windows local deployment. The frontend listens on `127.0.0.1:3001`, the backend on `127.0.0.1:8001`, and Nginx exposes `http://localhost:2026`.

## Configuration

Keep credentials in the private root `.env`. Connect to PostgreSQL at `127.0.0.1:5432` and to local Redis. The `database.postgres_url: $DATABASE_URL` configuration references the environment file.

Set `NGINX_HOME` to the directory containing `nginx.exe`. Back up its original configuration before copying the repository's `deploy/nginx/nginx.conf` to `conf/nginx.conf`. The proxy rewrites `/api/langgraph/*` to the backend's `/api/*` and keeps pages and requests on the same origin.

## Application lifecycle

After following [Quick Start](/docs/application/quick-start):

```bash
bash scripts/start.sh
bash scripts/stop.sh
```

The stop script stops the frontend, backend, and PostgreSQL container while preserving the database volume and Nginx.

## Nginx at boot

The proxy can be configured to start at system boot. No Windows login or personal password is required. The frontend and backend still start manually; until then, the proxy returns an unavailable-upstream response.

Manage the proxy separately using its installation. Managing a system-account process may require administrator privileges. Do not run the backend as an administrator during normal use.

## Data and safety

- PostgreSQL reuses `deer-flow-dev_postgres-data`. A missing existing volume causes startup to fail rather than silently initialize an empty database.
- Back up `backend/.deer-flow` separately: it contains attachments, artifacts, file-based memory and the generated login signing secret.
- Authentication is handled by the backend, not the Better Auth settings in older tutorials.
- Commands in the local sandbox run with the backend account's host permissions, without container isolation.
- The default configuration is local-only. Public deployment needs a separate security design, encrypted transport, network boundaries and backups.
