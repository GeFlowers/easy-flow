# DeerFlow 全量代码阅读顺序设计

## 目标

在仓库根目录生成 `CODE_READING_ORDER.md`，覆盖全部代码、测试、部署脚本与构建配置，并按照“上层功能到底层实现”的认知顺序组织。

## 组织方式

采用分层混合编号：

1. 产品与运行入口。
2. 前端页面和用户功能。
3. Gateway、渠道与调度应用层。
4. Agent、运行时和工具编排层。
5. 配置、持久化、沙箱及第三方集成底层。
6. 测试、技能脚本、部署和工程自动化。

关键入口文件单独编号；同一职责下的大量文件按文件夹编号。每个编号包含：

- 文件夹或单文件标题及超链接。
- 该编号所覆盖代码的中文作用说明。
- 建议阅读重点。
- 该组内全部具体代码文件的仓库相对超链接。

## 覆盖规则

纳入 Python、TypeScript、JavaScript、CSS、HTML、Shell、CMD、PowerShell、SQL、YAML、Dockerfile、Makefile 和迁移模板。排除说明文档、纯数据样例、图片、字体、依赖锁文件和生成物；测试、演示页面代码、CI 与构建配置仍纳入。

同一个代码文件只能出现一次。文件夹编号不能用一个目录链接代替内部文件清单，每个被纳入的文件都必须具有指向具体文件的链接。

## 排序规则

优先从用户可见功能和进程入口开始，再进入应用层编排、领域模块、运行时基础设施与持久化实现。测试紧随其对应模块或集中放入测试阶段；部署、开发工具和辅助脚本置于最后。

## 验证标准

- 文档链接集合与 Git 跟踪的纳入范围文件集合完全一致。
- 缺失链接、无效链接和重复链接均为零。
- 每个编号都有“作用”说明。
- Markdown 格式检查无尾随空格或无效链接格式。
- Git 提交只包含本次设计和最终阅读顺序文档，不包含无关工作区变更。
