# 通讯生成技能

## 概述

生成专业、研究充分的通讯，结合多来源精选内容与原创分析评论。遵循 Morning Brew、The Hustle、TLDR 和 Benedict Evans 等刊物的现代通讯实践，确保内容有信息量、吸引人且可执行。

输出是完整、可发布的 Markdown 通讯，适合邮件分发平台、网页发布，或转换为 HTML（HyperText Markup Language，超文本标记语言）。

## 核心能力

- 针对指定主题研究并精选多个网络来源。
- 以一致语气生成单主题或多主题通讯。
- 撰写吸引人的标题、摘要与原创评论。
- 组织内容，便于阅读和扫读。
- 支持每日摘要、每周综述、深度专题与行业简报。
- 包含相关链接、来源和署名。
- 依据技术人员、高管或普通读者调整语气。
- 以一致品牌和结构生成连续通讯系列。

## 使用时机

以下情况**始终加载**：

- 用户要求生成通讯、邮件摘要或内容综述。
- 用户需要某主题新闻或进展的精选摘要。
- 用户希望建立周期性通讯格式。
- 用户要求将领域近期进展整理为简报。
- 用户需要一份包含多个精选条目、可直接用于邮件的内容。
- 用户要求“每周综述”、“月度摘要”或“晨间简报”。

## 通讯流程

### 第 1 阶段：规划

#### 第 1.1 步：理解要求

识别关键参数：

| 参数 | 说明 | 默认值 |
| --- | --- | --- |
| **主题** | 主要覆盖领域 | 必填 |
| **格式** | 每日摘要、每周综述、深度专题、行业简报 | 每周综述 |
| **读者** | 技术、高管、普通或小众社群 | 普通 |
| **语气** | 专业、口语、幽默或分析 | 口语而专业 |
| **长度** | 短篇约 5 分钟、中篇约 10 分钟、长篇 15 分钟以上 | 中篇 |
| **章节** | 内容章节数量和类型 | 4–6 节 |
| **频率背景** | 单次或连续系列的一期 | 单次 |

#### 第 1.2 步：定义结构

按格式选择合适结构。

**每日摘要：**

```
1. 头条（1 条，详细）
2. 快讯（3–5 条，简短）
3. 今日数据或金句
4. 值得关注
```

**每周综述：**

```
1. 编者按／引言
2. 头条（2–3 条，详细）
3. 趋势与分析（1–2 条，原创评论）
4. 简讯（4–6 条，简短摘要）
5. 工具与资源（2–3 条）
6. 最后再聊一件事／结尾
```

**深度专题：**

```
1. 引言与背景
2. 背景／为何重要
3. 关键进展（详细分析）
4. 专家视角
5. 下一步／影响
6. 延伸阅读
```

**行业简报：**

```
1. 执行摘要
2. 市场动态
3. 公司新闻与行动
4. 产品与技术更新
5. 监管与政策变化
6. 数据与指标
7. 展望
```

### 第 2 阶段：研究与精选

#### 第 2.1 步：多来源研究

使用网页搜索开展充分研究。**通讯质量直接取决于研究的质量和时效性。**

**搜索策略：**

```
# 当前新闻与进展
“[主题] 新闻 [当前月份] [当前年份]”
“[主题] 最新进展”
“[主题] 本周公告”

# 趋势与分析
“[主题] 趋势 [当前年份]”
“[主题] 分析 专家观点”
“[主题] 行业报告”

# 数据与统计
“[主题] 统计 [当前年份]”
“[主题] 最新市场数据”
“[主题] 增长指标”

# 工具与资源
“[主题] 新工具 [当前年份]”
“[主题] 开源发布”
“最佳 [主题] 资源 [当前年份]”
```

> **重要：** 始终检查 `<current_date>`，确保查询使用正确时间背景，绝不写死年份。

#### 第 2.2 步：评估与选择来源

| 标准 | 优先考虑 |
| --- | --- |
| **时效性** | 最近 7–30 天的内容 |
| **权威性** | 一手来源、官方公告、成熟刊物 |
| **独特性** | 新视角或报道不足的故事 |
| **相关性** | 每项明确关联通讯主题 |
| **可执行性** | 读者能采用的工具、洞察、策略 |
| **多样性** | 混合新闻、分析、数据和实用资源 |

#### 第 2.3 步：深入提取内容

关键故事使用 `web_fetch` 阅读全文并提取：

1. **核心事实：** 发生什么、涉及谁、何时。
2. **背景：** 为什么重要、背景信息。
3. **数据：** 具体数字、指标或统计。
4. **引言：** 相关专家引用或官方声明。
5. **影响：** 对读者意味着什么。

### 第 3 阶段：写作

#### 第 3.1 步：通讯抬头

每期以一致抬头开场：

```markdown
# [通讯名称]

*[标语或说明]——[日期]*

---

[可选：一句话预告本期内容]
```

#### 第 3.2 步：章节写作指南

**头条／精选条目：**

- **标题：** 吸引人、清晰、突出价值，不做标题党。
- **引子：** 1–2 句让读者关心。
- **正文：** 2–4 段关键事实和背景。
- **为何重要：** 1 段关联读者世界。
- **来源链接：** 始终标明并链接原始来源。

**简讯：**

- **格式：** 加粗标题＋2–3 句摘要＋来源链接。
- **重点：** 每项只有一个关键收获。
- **效率：** 读者无需点击也能获得核心洞察。

**分析／评论：**

- **观点：** 对趋势和进展的独特理解。
- **结构：** 观察 → 背景 → 影响 → 可选行动建议。
- **证据：** 每个主张由数据或有来源的信息支持。

#### 第 3.3 步：写作标准

| 原则 | 实施 |
| --- | --- |
| **便于扫读** | 使用标题、加粗、列表、短段落 |
| **吸引人** | 从最有趣角度切入，不必按时间顺序 |
| **简练** | 每句话都有价值，删去填充 |
| **准确** | 每项事实有来源，每个数字经验证 |
| **注明出处** | 用行内链接认可原始来源 |
| **有人情味** | 像知识丰富的朋友，不像新闻通稿 |

**按受众调整语气：**

| 受众 | 语气 | 示例 |
| --- | --- | --- |
| **技术人员** | 精确，假设已有专业知识 | “新接口支持流式远程调用，通过流量控制窗口处理背压。” |
| **高管** | 聚焦影响、结果和战略 | “此次收购让甲公司在企业市场拥有 40% 份额，直接威胁乙公司的定价权。” |
| **普通读者** | 通俗、类比、解释概念 | “可以把它当成数据的通用翻译器，让任何应用与任何数据库交流，不必学习新语言。” |

### 第 4 阶段：组装与打磨

#### 第 4.1 步：组装

按照选定结构模板，将所有章节组合成最终文档。

#### 第 4.2 步：页尾

每期以以下内容结束：

```markdown
---

*[通讯名称]是[用途说明]。*
*[如何订阅、分享或反馈]*

*来源：所有链接均在正文中提供。本通讯精选并总结公开信息，
同时提供原创评论。*
```

#### 第 4.3 步：质量清单

定稿前检查：

- [ ] **每个事实主张都有来源链接**，没有无依据断言。
- [ ] **链接有效**，来自搜索结果的已验证地址。
- [ ] **日期引用符合真实当前日期**，不写死或猜测。
- [ ] **内容及时**，主要条目均在预期时间范围内。
- [ ] **没有重复故事**，每项只出现一次。
- [ ] **格式一致**，标题、列表和链接风格统一。
- [ ] **覆盖平衡**，不被单一来源或视角主导。
- [ ] **长度合适**，符合目标。
- [ ] **开头吸引人**，前两句让人愿意继续读。
- [ ] **结尾清晰**，令人记得或可以行动。
- [ ] **完成校对**，没有错字、格式错误或残句。

## 调整示例

### 科技通讯

- 表情符号：适量，用于章节标题。
- 章节：头条、深度专题、简讯、开源聚焦、开发工具。
- 语气：技术而口语。

### 商业／金融通讯

- 表情符号：极少或不用。
- 章节：市场概览、交易动态、公司新闻、数据角、展望。
- 语气：专业、分析。

### 垂直行业通讯

- 表情符号：适量。
- 章节：监管更新、市场数据、创新观察、人事变动、活动。
- 语气：专家、权威。

### 创意／营销通讯

- 表情符号：可较多使用。
- 章节：营销活动聚焦、趋势观察、本周爆款、喜爱的工具、灵感。
- 语气：热情而专业。

## 输出处理

生成后：

- 保存到 `/mnt/user-data/outputs/newsletter-{topic}-{date}.md`。
- 使用 `present_files` 向用户展示。
- 可调整章节、语气、长度或关注领域。
- 用户要求网页输出时，说明可使用标准工具转换 Markdown。

## 注意事项

- 与 `deep-research` 组合可更全面覆盖；需要深度分析时同时加载。
- 搜索和通讯日期引用始终使用 `<current_date>`。
- 周期性通讯保持一致结构，帮助读者形成预期。
- 精选重质不重量，5 个优秀条目胜过 15 个普通条目。
- 正确标注所有来源，通过透明出处建立信任。
- 避免总结读者无法访问的付费内容。
- 用户提供指定地址或文章时，与精选发现一并纳入。
- 摘要自身应有足够价值，即使不逐一点击链接也有收获。
